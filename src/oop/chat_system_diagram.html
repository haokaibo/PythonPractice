Design highlights:设计要点： ① Message.message_id uses Snowflake for monotonic ordering — clients sort by ID to guarantee sequence; ② Message.idempotency_key for idempotent dedup (short-term Redis Set + DB unique index as backstop); ③ Conversation.read_cursor uses a per-user "read cursor" instead of per-message read flags — cross-device sync only needs one msg_id; ④ INotificationChannel abstracts APNs / FCM, making new channels (e.g. WebPush) easy to add; ⑤ GroupConversation extends Conversation, discriminated by kind (DM / GROUP); ⑥ fanOutToMembers() is fan-out on write (≤100-member groups, write amplification ×N, O(1) read). Switching to fan-out on read removes this method and makes listMessages() query membership in real time — no write amplification, but one extra read per pull. Mentioning this trade-off proactively in an interview is a bonus. ① Message.message_id 用 Snowflake 算法保证单调递增，客户端按 ID 排序即保证顺序； ② Message.idempotency_key 用于幂等去重（Redis Set 短期 + 数据库唯一索引兜底）； ③ Conversation.read_cursor 用“已读位点”代替逐条已读，多端同步时只传一个 msg_id； ④ INotificationChannel 抽象 APNs / FCM，便于扩展 WebPush 等新通道； ⑤ GroupConversation 继承 Conversation，通过 kind 区分 DM / GROUP； ⑥ fanOutToMembers() 是写扩散（≤100 人群组，写入放大 ×N，读取 O(1)）；若改为读扩散，则去掉此方法，listMessages() 内部实时查 membership，写入无放大但读取多一次查询——面试时主动提这个 trade-off 是加分项。

High-availability highlights:高可用要点： ① All stateless services (ConnGW / Chat / Presence / Notif) deploy ≥2 replicas in each AZ; LB health checks evict failed instances; ② Cosmos DB primary/replica async-replicates across AZs; on single-AZ failure, read traffic auto-fails over to the replica AZ; ③ Redis master/replica spans AZs; if the routing table is unavailable, ConnGW falls back to a local LRU cache and rebuilds; ④ Kafka RF=3 across AZs with min.insync=2 guarantees no message loss under single-AZ failure; ⑤ Chaos engineering can be introduced: randomly kill a ConnGW instance and verify WS clients auto-reconnect to the other AZ. ① 所有无状态服务（ConnGW / Chat / Presence / Notif）在两个 AZ 各部署 ≥2 副本，LB 健康检查剔除故障实例； ② Cosmos DB 主从跨 AZ 异步复制，单 AZ 故障时读流量自动切到副本 AZ； ③ Redis 主从跨 AZ，连接路由表故障时 ConnGW 用本地 LRU 兜底 + 重建； ④ Kafka RF=3 跨 AZ，min.insync=2 保证单 AZ 故障不丢消息； ⑤ 可引入 chaos engineering：随机 kill 一个 ConnGW 实例，验证 WS 客户端自动重连到另一 AZ。
